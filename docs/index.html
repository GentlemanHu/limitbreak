LimitBreak

Hit the Claude Code usage limit, walk away. LimitBreak continues the same session the moment real quota comes back.

Download for macOS Source on GitHub 
curl -fsSL https://raw.githubusercontent.com/GentlemanHu/limitbreak/main/scripts/install.sh | LIMITBREAK_REPO=GentlemanHu/limitbreak bash

Real quota

5-hour, weekly and per-model windows read through CLIProxyAPI. Unknown stays unknown — never shown as 0%.

Same session, same model

Only the continue text is sent. Model, account and permission mode are left alone.

Silent delivery

Uses Claude Code's own message socket: no window switching, works with the screen locked. A closed session is woken in the background first.

Live clocks

See the next quota check and the expected auto-continue time for every session.

Safe by default

Explicit consent, emergency pause, hourly caps, circuit breaker, and no resend on uncertain results.

Extensible

Pluggable quota sources, session observers and executors. Codex and Antigravity quota already observed.

“LimitBreak is damaged and can't be opened”?

Builds that are not notarized by Apple get this message after a browser download. The app is fine; remove the quarantine attribute once:

xattr -dr com.apple.quarantine /Applications/LimitBreak.app

额度守护 · 中文

撞上 Claude Code 的 5 小时或每周额度上限后，LimitBreak 通过 CLIProxyAPI 查看真实额度，等额度真正恢复，就在原来的会话里发送「继续」。只发继续文案，不改模型、不抢键盘，锁屏也能后台直发；每个会话都有「下次查询」和「预计自动继续」倒计时。免费开源（MIT），支持 Apple Silicon 与 Intel，需要 macOS 14 及以上。

提示「已损坏」时执行：xattr -dr com.apple.quarantine /Applications/LimitBreak.app
